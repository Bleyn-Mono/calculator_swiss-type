# .project-rules.md

## 1. General Principles & Paradigm

* **OOP First**: Весь код должен быть строго организован в классы. Избегать функционального стиля для бизнес-логики.
* **Separation of Concerns (SoC)**: Логика расчетов, интерфейс и управление данными (JSON/File) должны быть разделены. Классы UI не должны содержать математических формул.
* **Data Flow**: UI собирает данные  -> передает их в Calculator -> Calculator создает объекты Операций -> Calculator сохраняет результат в TXT.

## 2. Base Entities & Architecture

### 2.1 Операции (Operations)

Для каждого типа обработки создается отдельный класс. Все классы операций должны иметь унифицированный интерфейс для хранения входных данных.

* **Перечень классов**: `FacingOp`, `TurningOp`, `MillingOp`, `DrillingG1Op`, `DrillingQOp`, `SlottingOp`, `WhirlingOp`, `ThreadingOp`.
* **Назначение**: Хранение параметров, введенных пользователем (подача, скорость, глубина, длина и т.д.).

### 2.2 Калькулятор (Calculator System)

* **Base Calculator**: Содержит общие математические методы и базовые формулы.
* **Specific Calculators**: Наследуют базовый класс и реализуют специфику конкретных операций.
* **JSON Integration**: В начале сессии калькулятор подгружает константы станка (время смены инструмента, ускорения) из внешнего `config.json`.

### 2.3 Интерфейс (UI)

* **Библиотека**: `customtkinter`.
* **Структура**: Одно окно, разделенное на два логических блока: **Main Spindle** и **Back Spindle**.
* **Thread Management**: Расчеты должны выполняться в основном потоке (потоки не требуются), так как математические операции над пользовательским вводом не являются ресурсоемкими.

## 3. Data Management & State

### 3.1 Хранение параметров (JSON)

* Все специфические данные станков хранятся в `machines_config.json`.
* Программа должна считывать файл один раз при выборе станка. Файл должен быть доступен для редактирования пользователем после компиляции.

### 3.2 Результаты (State)

* Результат каждого расчета записывается в текстовый файл (`.txt`).
* **Имя файла**: Берется из поля ввода в UI.
* **Поведение**: Если файл с таким именем существует, он перезаписывается без предупреждения.

## 4. Coding Style (Strict)

### 4.1 Type Hinting

* **Обязательно 100% покрытие**. Каждый метод и каждый аргумент должны иметь аннотацию типа.
* *Пример*: `def calculate(self, data: float) -> float:`
* Это необходимо для безошибочного анализа кода ИИ-агентом.

### 4.2 Documentation

* **Docstrings обязательны** для каждого класса и метода.
* Должны кратко описывать назначение и формулу (если применимо).

### 4.3 Naming Conventions

* **Классы**: `PascalCase` (напр. `MillingOperation`).
* **Методы и переменные**: `snake_case` (напр. `get_operation_time`).
* **Константы**: `UPPER_CASE` (напр. `DEFAULT_SAFETY_DISTANCE`).

## 5. Error Handling

* Проверка входных данных из UI на соответствие типам (валидация `float/int`).
* Обработка отсутствия ключей в `machines_config.json` с выводом ошибки в консоль или статус-бар UI.

## 6. Technologies used

* **OS**: Windows 11
* **Python**: 3.10+
* **Libs**: `customtkinter`, `json`, `typing`

## 7. Project Structure

Для обеспечения масштабируемости и соблюдения SoC (Separation of Concerns), проект организован следующим образом:

```text
/calculator
├── main.py                # Точка входа (запуск приложения)
├── GEMINI.md              # Инструкции и правила проекта
├── machines_config.json   # Конфигурация станков (JSON)
├── requirements.txt       # Список зависимостей
├── gui/                   # Графический интерфейс (customtkinter)
│   ├── __init__.py
│   ├── app.py             # Главное окно и логика переключения вкладок
│   ├── main_spindle.py    # Интерфейс главного шпинделя
│   └── back_spindle.py    # Интерфейс противошпинделя
├── core/                  # Бизнес-логика и математика
│   ├── __init__.py
│   ├── base_calculator.py # Базовые формулы и методы
│   ├── operations.py      # Классы FacingOp, TurningOp и т.д.
│   └── specific_calc.py   # Наследники BaseCalculator
├── utils/                 # Вспомогательные инструменты
│   ├── __init__.py
│   ├── config_loader.py   # Логика чтения JSON
│   └── file_exporter.py   # Логика записи результатов в TXT
├── output/                # Директория для сгенерированных .txt отчетов
└── assets/                # Ресурсы (иконки, стили)
```
