# Объектно-Ориентированное Программирование (ООП)

## 1. Core Concepts

ООП — это способ организации кода, где данные и функции для работы с ними объединяются в сущности, называемые **объектами**.

* **Класс (Class)**: Чертеж или шаблон. Например, класс `DrillingOp` описывает, какие данные нужны для любого сверления.
* **Объект (Object/Instance)**: Конкретный экземпляр. Например, «Сверление отверстия №1 на 10 мм» — это объект класса `DrillingOp`.
* **Четыре столпа ООП**:
1. **Инкапсуляция**: Скрытие внутренней логики внутри класса. UI не должен знать, по какой формуле считается время, он просто вызывает метод `.calculate()`.
2. **Наследование**: Создание новых классов на базе существующих. Твой `Calculator` будет наследовать общие методы из базового класса.
3. **Полиморфизм**: Возможность использовать один и тот же интерфейс для разных типов (например, у всех классов операций есть метод `get_data()`, но возвращают они разные параметры).
4. **Абстракция**: Выделение только важных характеристик объекта (для сверления нам важна глубина и подача, но не важен цвет сверла).

## 2. Syntax

### 2.1 Создание базового класса и конструктор

Конструктор `__init__` инициализирует объект данными при его создании.

```python
class BaseOperation:
    def __init__(self, name: str, op_type: str):
        self.name = name  # Аттрибут класса
        self.op_type = op_type

    def get_info(self) -> str:
        return f"Операция: {self.name} ({self.op_type})"
```

### 2.2 Наследование

Класс-потомок получает все методы родителя и может добавлять свои.

```python
class DrillingOp(BaseOperation):
    def __init__(self, name: str, depth: float, feed: float):
        # Вызов конструктора родителя
        super().__init__(name, "Сверление")
        self.depth = depth
        self.feed = feed

    def calculate_basic_time(self) -> float:
        return self.depth / self.feed
```

### 2.3 Приватные аттрибуты

В Python принято помечать внутренние данные нижним подчеркиванием, чтобы UI случайно их не изменил.

```python
class Calculator:
    def __init__(self):
        self._machine_constants = {} # Приватный аттрибут
```

## 3. Best Practices

### 3.1 Принцип единственной ответственности (SRP)

Один класс — одна задача.

* Класс `FacingOp` только хранит данные торцовки.
* Класс `Calculator` только считает.
* Не смешивай расчеты и создание кнопок в одном классе.

### 3.2 Использование Type Hinting (обязательно для твоего проекта)

Это помогает ИИ-агенту понимать, какие объекты передаются между классами.

```python
def process_op(operation: DrillingOp) -> float:
    return operation.calculate_basic_time()
```

### 3.3 Composition over Inheritance (Композиция вместо наследования)

Если класс `Calculator` использует данные из JSON, не делай его наследником "Класса-Чтения-JSON". Просто передай данные JSON внутрь калькулятора как аргумент.

## 4. Error Handling

### 4.1 Проверка типов при инициализации

На слабом ПК ошибки лучше ловить на взлете, чтобы программа не "падала" в середине сложного расчета.

```python
class TurningOp(BaseOperation):
    def __init__(self, length: float):
        if not isinstance(length, (int, float)):
            raise ValueError("Длина должна быть числом")
        self.length = length
```

### 4.2 Обработка отсутствующих методов

Если ты вызываешь расчет для операции, которая еще не реализована:

```python
class BaseCalculator:
    def calculate(self):
        # Если метод не переопределен в наследнике — выдаем ошибку
        raise NotImplementedError("Метод calculate должен быть реализован в подклассе")
```

### 4.3 AttributeError

Возникает, когда ты пытаешься обратиться к аттрибуту, которого нет в конкретном типе операции.

```python
try:
    print(current_op.depth)
except AttributeError:
    print("У этой операции нет параметра 'глубина'")
```
