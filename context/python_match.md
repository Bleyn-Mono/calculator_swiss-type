# Структурное сопоставление шаблонов (match/case)

## 1. Core Concepts

* **Декларативность**: Вместо того чтобы проверять каждое условие вручную (`if x == 1 and y == 2`), вы описываете «форму» данных, которую ожидаете увидеть.
* **Распаковка (Destructuring)**: `match` может одновременно проверять тип данных и извлекать из них значения в переменные.
* **Первое совпадение**: Как и в `if-elif`, выполняется только первый подошедший блок `case`.
* **Мягкое ключевое слово**: `match` и `case` являются «мягкими» ключевыми словами. Это значит, что вы по-прежнему можете использовать их как имена переменных в других частях кода (хотя это не рекомендуется).

## 2. Syntax

### 2.1 Базовое сопоставление

```python
command = "START"

match command:
    case "START":
        print("Запуск системы")
    case "STOP":
        print("Остановка")
    case _:
        print("Неизвестная команда") # _ — это шаблон-заглушка (wildcard)
```

### 2.2 Сопоставление структур (Списки и Кортежи)

Это особенно полезно для парсинга параметров G-кода:

```python
# Представим, что мы разбили строку G-кода в список: ["G01", "X100", "Y50"]
cmd_parts = ["G01", "X100", "Y50"]

match cmd_parts:
    case ["G00", x]:
        print(f"Быстрое перемещение в {x}")
    case ["G01", x, y]:
        print(f"Линейная интерполяция: {x}, {y}")
    case ["G01", *coords]:
        print(f"Линейная интерполяция с набором координат: {coords}")
```

### 2.3 Использование "Guards" (Защитные условия)

Вы можете добавить дополнительную проверку `if` прямо в строку `case`:

```python
match command:
    case "SET_SPEED" if machine_ready:
        print("Установка скорости")
    case "SET_SPEED":
        print("Ожидание готовности станка...")
```

### 2.4 Объединение шаблонов (`|`)

```python
match code:
    case "M03" | "M04":
        print("Команда вращения шпинделя")
```

## 3. Best Practices

### 3.1 Используйте `_` для безопасности

Всегда завершайте конструкцию блоком `case _:`. Если ни один шаблон не подошел и этого блока нет, программа просто пойдет дальше, что может привести к скрытым логическим ошибкам.

### 3.2 Match против If-Else

* Используйте `if-else` для простых сравнений (например, `if x > 5`).
* Используйте `match` для проверки **структуры** или **типа** данных (например, когда пришла строка или список).

### 3.3 Имена переменных в шаблонах

Помните, что любое имя в `case` (кроме заранее определенных констант) воспринимается как создание новой переменной.

```python
# ОШИБКА: Python подумает, что вы хотите записать значение в переменную STATUS
STATUS = "OFF"
match current_val:
    case STATUS: # Это НЕ сравнение с "OFF", это создание переменной STATUS
        print("Это сработает всегда")
```

Для сравнения с константой используйте точечную нотацию (например, `Settings.STATUS`).

## 4. Error Handling

### 4.1 SyntaxError (Старые версии Python)

Поскольку `match` появился в Python 3.10, на более старых версиях код выдаст ошибку синтаксиса. Поскольку у вас **Mac M2**, у вас наверняка стоит актуальная версия, но при развертывании на других ПК (например, на старых цеховых компьютерах) это нужно учитывать.

### 4.2 Ошибки распаковки

Если вы ожидаете определенное количество элементов, но данные пришли в другом формате:

```python
data = [1, 2, 3]

try:
    match data:
        case [x, y]: # Ожидалось 2 элемента, а пришло 3
            print(x, y)
except Exception as e:
    # Match сам по себе не падает при несовпадении количества, 
    # он просто переходит к следующему case. 
    # Ошибка может возникнуть только внутри блока выполнения.
    pass
```
