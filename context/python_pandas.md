# Библиотека Pandas (Оптимизированная версия)

## 1. Core Concepts

* **Память — главный ресурс**: На слабых ПК с Windows 11 (где сама ОС забирает 3-4 ГБ ОЗУ) каждый мегабайт на счету. Pandas по умолчанию использует 64-битные типы данных, что избыточно для простых расчетов времени.
* **Векторизация против Циклов**: Даже на слабом процессоре векторизованные операции Pandas работают быстрее, чем циклы `for`, так как они написаны на языке C.
* **Типизация**: Принудительное понижение точности (например, с `float64` до `float32`) может сократить потребление памяти в **2 раза**.

## 2. Syntax

### 2.1 Чтение данных с экономией памяти

При чтении G-кода указывайте только нужные столбцы (`usecols`) и оптимизированные типы данных (`dtype`).

```python
import pandas as pd
import numpy as np

# Читаем только колонки 'command' и 'time', экономя ОЗУ
df = pd.read_csv("log.csv", usecols=['command', 'time'], dtype={'time': np.float32})
```

### 2.2 Чтение большими кусками (Chunking)

Если файл G-кода весит десятки мегабайт, читайте его частями:

```python
chunk_size = 1000
for chunk in pd.read_csv("large_gcode.csv", chunksize=chunk_size):
    # Обрабатываем по 1000 строк за раз
    process(chunk)
```

### 2.3 Быстрая агрегация

```python
# Вместо создания множества промежуточных таблиц, используйте методы "на месте"
total_cycle_time = df['time'].sum()
```

## 3. Best Practices (Для слабых ПК)

### 3.1 Очистка мусора

После тяжелых вычислений принудительно удаляйте временные таблицы, чтобы Windows 11 не начала использовать файл подкачки (это замедлит программу в десятки раз).

```python
import gc
del temporary_df
gc.collect() # Принудительная очистка памяти
```

### 3.2 Избегайте визуализации тяжелых таблиц

Не пытайтесь отобразить в GUI (PyQt/CustomTkinter) таблицу на 100,000 строк. Пользователю это не нужно, а слабый ПК «зависнет» при отрисовке. Отображайте только первые 50-100 строк или финальные итоги.

### 3.3 Использование `.itertuples()` вместо `.iterrows()`

Если векторизация невозможна и нужен цикл, используйте `.itertuples()`. Это гораздо быстрее и потребляет меньше памяти.

## 4. Error Handling

### 4.1 MemoryError

Самая вероятная ошибка на слабом железе.

```python
try:
    df = pd.read_csv("massive_file.csv")
except MemoryError:
    print("Ошибка: Недостаточно оперативной памяти. Попробуйте закрыть другие программы.")
```

### 4.2 EmptyDataError

Если станок выдал пустой лог, программа не должна падать.

```python
try:
    df = pd.read_csv("empty.txt")
except pd.errors.EmptyDataError:
    df = pd.DataFrame() # Создаем пустую таблицу, чтобы логика не сломалась
```
