# Обработка исключений (try / except)

## 1. Core Concepts

### 1.1 Исключение (Exception)

Это событие, которое происходит во время выполнения программы и нарушает её нормальный ход (ошибка в логике, нехватка памяти, отсутствие файла).
Термин EAFP (Easier to Ask for Forgiveness than Permission) - это идеологическая база Python.

```python
# Программа падает моментально, последующий код никогда не выполнится
1 / 0  
print("Этот текст мы никогда не увидим")
```

### 1.2 Блок try

Содержит код, в котором потенциально может возникнуть ошибка. Python «пробует» выполнить этот код.

### 1.3 Блок except

Содержит код, который выполнится только если в блоке try возникла ошибка. Это «подушка безопасности».

### 1.4 Проброс ошибки

Если ошибка возникла, но не была поймана в except, программа аварийно завершается и выводит Traceback (отчет об ошибке).

```python
try:
    int("строка") # Вызывает ValueError
except ZeroDivisionError: # Ловит ТОЛЬКО деление на ноль!
    print("Не поймает")   # Программа всё равно упадет с ValueError
```

Программа выведет именно Traceback

## 2 Syntax

### 2.1 Базовая конструкция

```Python
try:
    number = int(input("Введите число: "))
    print(100 / number)
except ValueError:
    print("Ошибка: Вы ввели не число!")
except ZeroDivisionError:
    print("Ошибка: На ноль делить нельзя!")
```

2.2 Полная форма (else и finally)

```Python
try:
    file = open("data.txt", "r")
    content = file.read()
except FileNotFoundError:
    print("Файл не найден")
else:
    print("Файл прочитан успешно") # Выполнится, если в try НЕ БЫЛО ошибок
finally:
    file.close()
    print("Завершение работы с файлом") # Выполнится ВСЕГДА (удобно для закрытия ресурсов)
```

### 2.3 Получение данных об ошибке

```Python
try:
    x = 1 / 0
except ZeroDivisionError as e:
    print(f"Произошла техническая ошибка: {e}") # e содержит текст "division by zero"
```

## 3 Best Practices

### 3.1 Специфичность

Всегда указывайте конкретный тип ошибки `except ValueError`. Избегайте «голого» `except`:, так как он ловит даже системные прерывания (например, Ctrl+C), что затрудняет остановку программы.
except Exception: — это максимум, до которого стоит опускаться. Использовать просто except: (без указания класса) — грубая ошибка.

### 3.2 Минимум кода в try

Помещайте в блок try только те строки, которые действительно могут вызвать исключение. Это помогает точнее понять, где именно произошел сбой.

### 3.3 Не подавляйте ошибки молчаливо

Если вы используете `except: pass`, вы никогда не узнаете, что программа работает неправильно. Как минимум, логируйте ошибку.

### 3.4 Используйте finally для очистки:

Это важно для освобождения памяти или закрытия соединений с периферией.

## 4 Error Handling (Ошибки в самих исключениях)

### 4.1 Цепочка исключений

Иногда ошибка возникает внутри самого блока except. Python запоминает первопричину.

```Python
try:
    # какой-то код
    pass
except KeyError:
    # Ошибка в обработчике ошибки
    raise RuntimeError("Критический сбой при обработке ключа")
```

### 4.2 Иерархия исключений

Все стандартные ошибки (`ValueError`, `TypeError` и т.д.) являются «детьми» общего класса `Exception`.
Все ошибки в Python организованы в дерево. 
- BaseException (самый корень)
    - SystemExit, KeyboardInterrupt (системные, их ловить нельзя)
    - Exception (базовый класс для всех обычных ошибок)
        - ArithmeticError
            - ZeroDivisionError
        - LookupError
            - IndexError
            - KeyError
        - ValueError

```Python
try:
    # Код
    pass
except Exception as e:
    # Поймает почти любую ошибку, но использовать осторожно!
    print(f"Поймана непредвиденная ошибка: {type(e).__name__}")
```
