# Работа со строками (str)

## 1. Core Concepts

* **Иммутабельность**: Строки в Python неизменяемы. Любая операция (замена символа, склейка) создает в памяти **новую** строку. Это важно учитывать при обработке больших G-код файлов на слабых ПК.
* **Юникод**: Python 3 использует UTF-8 по умолчанию. Это позволяет легко работать с комментариями в коде на русском или немецком языках.
* **Строка как последовательность**: Строка ведет себя как список символов. Вы можете обращаться к ним по индексу или делать срезы.
* **Интернирование**: Python оптимизирует память, сохраняя только одну копию коротких строк с одинаковым содержанием.

## 2. Syntax

### 2.1 Создание и форматирование

```python
# F-строки (Самый быстрый и современный способ)
axis = "X"
value = 120.5
command = f"G01 {axis}{value} F1500"

# Многострочные строки (удобно для справок по M-кодам)
manual = """
M03 - Шпиндель по часовой
M04 - Шпиндель против часовой
"""
```

### 2.2 Основные методы

```python
line = "  G01 X100.5 Y20.0  ; Линейная интерполяция  "

# Очистка от пробелов и лишних символов
clean_line = line.strip() 

# Разделение строки (критично для парсинга G-кода)
parts = clean_line.split() # ['G01', 'X100.5', 'Y20.0', ';', 'Линейная', ...]

# Поиск и замена
if "G01" in clean_line:
    new_line = clean_line.replace("G01", "G1")
```

### 2.3 Срезы (Slices)

```python
s = "G01X100"
cmd = s[:3]   # "G01"
val = s[3:]   # "X100"
```

## 3. Best Practices (Оптимизация для Windows 11)

### 3.1 Склейка через `.join()`

Никогда не склеивайте большое количество строк в цикле через `+`. Это создает тысячи промежуточных объектов в памяти и сильно тормозит компьютер.

* **Плохо**: `s += "new line\n"`
* **Хорошо**:

```python
lines = ["G01 X10", "G01 X20", "G01 X30"]
final_text = "\n".join(lines) # В разы быстрее и экономнее по памяти
```

### 3.2 Использование методов вместо RegEx

Регулярные выражения (`re`) мощные, но медленные. Если вам нужно просто проверить начало строки или наличие подстроки, используйте:

* `line.startswith("G01")` вместо поиска шаблоном.
* `line.endswith(";")` для поиска комментариев.

### 3.3 Обработка комментариев

Для инженерного софта важно быстро отделять код от пояснений:

```python
raw_line = "G01 X100 ; это комментарий"
code_part = raw_line.split(';')[0].strip() # Получим только "G01 X100"
```

## 4. Error Handling

### 4.1 IndexError

Возникает при попытке взять индекс или срез у пустой строки (например, пустая строка в файле G-кода).

```python
line = ""
try:
    char = line[0]
except IndexError:
    print("Ошибка: Строка пуста")
```

### 4.2 ValueError (при конвертации)

Часто случается при попытке превратить извлеченную координату в число.

```python
coord_str = "X100.5"
try:
    # Ошибка, так как 'X' нельзя превратить в float
    value = float(coord_str) 
except ValueError:
    # Правильный подход: убираем букву оси
    value = float(coord_str[1:])
```

### 4.3 UnicodeDecodeError

Возникает на Windows, если файл сохранен в кодировке `Windows-1251` (CP1251), а вы открываете его как `UTF-8`.

```python
try:
    with open("program.nc", encoding="utf-8") as f:
        content = f.read()
except UnicodeDecodeError:
    # Пробуем стандартную кодировку Windows для станков
    with open("program.nc", encoding="cp1251") as f:
        content = f.read()
```
